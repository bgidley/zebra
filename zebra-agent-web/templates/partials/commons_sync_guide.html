Set up skill sync between your devices Show steps Hide steps

Skill sync lets the skills you build with me at home and at work follow you. Two deployments of one Zebra (say a home server and a work laptop) share workflows only. Memories, knowledge, values, runs and anything about you never leave the device. I scan every workflow for personal and confidential data before it is sent, and ask you before I send or adopt it.

  1. Set up the private relay (once, on your home host)

    The relay passes encrypted workflows between your devices. Whoever runs the host follows specs/commons-sync-relay-runbook.md: steps 1 to 3 now (operator key, relay containers, the /sync route), and step 4, registering your Zebra key on the relay, once you have started your Zebra in step 3 below. You get two values: the relay URL wss://<host>/sync and the receipt key.

  2. Turn sync on for each deployment

    Add these to its site env file (~/.config/zebra/site.env on the Podman host), then retry the latest master pipeline's deploy job. Only a deploy copies the site env into what the containers read; a restart alone changes nothing:

    ZEBRA_COMMONS_ENABLED=1
ZEBRA_SYNC_RELAY=wss://<host>/sync
ZEBRA_SYNC_RECEIPT_PUBKEY=<receipt key>
# optional
ZEBRA_SYNC_DIRECTION=both          # send / receive / both / off
ZEBRA_SYNC_CONFIDENTIAL_PATTERNS=  # regexes that block a send

  3. Home: start your Zebra and back up its key

    On this page choose Start a new Zebra, then Show backup key and store it offline. The device that starts the Zebra holds its key and is the only one that can pair or revoke devices.

  4. Work: copy the pairing code

    Open Commons on the work deployment and copy its pairing code (npub1…). Note its fingerprint. Do not start a new Zebra there: a device that has its own Zebra cannot join another.

  5. Home: pair the work device

    Under Pair a device, paste the code and check the fingerprint matches. Choose sphere work, and Someone else if your employer manages that machine; I then ask you before each skill it shares. Copy the certificate code (zcert1…) I show you.

  6. Work: join

    Paste the certificate code under Join this Zebra to an existing one. The work page now shows the same Zebra key as home. Within a daemon tick or two both devices publish their certificates and find each other on the relay.

  7. Check it works

    At work, run a workflow you want at home and approve the share in Tasks when I ask. Soon after it appears in the home Workflows library, and its genealogy shows where it came from. If the relay is down, shares wait in a queue and go when it is back.

Lost or retired a device? Revoke it under Devices on the home deployment. Skills it shared earlier stay; anything new from it is refused.

Turning it off: remove ZEBRA_SYNC_RELAY from the site env file and retry the latest deploy job, or set ZEBRA_SYNC_DIRECTION=off. Nothing is lost; queued shares wait for next time.
