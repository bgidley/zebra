## ADDED Requirements

### Requirement: Stack creates only Always Free resources
The Resource Manager stack in `deploy/oci/` SHALL create only Always Free resources: one
`VM.Standard.A1.Flex` instance of at most 2 OCPU and 12 GB with an ephemeral public IP, block
storage of at most 200 GB in total, one Autonomous Database with `is_free_tier = true`, a
`DEFAULT` vault with `SOFTWARE` keys, and free networking (VCN, subnet, internet gateway, route
table, security list) and Object Storage. It SHALL NOT create load balancers, NAT gateways, DRGs,
reserved public IPs or HSM keys.

#### Scenario: Default plan
- **WHEN** the stack is planned with only the required variables
- **THEN** the instance is A1.Flex at 2 OCPU / 12 GB, the ADB has `is_free_tier = true` and
  requires mTLS, the vault is `DEFAULT`, the key is `SOFTWARE`, and the only ingress rule is
  TCP 443

#### Scenario: Limit raised in code
- **WHEN** a local raises the shape, OCPU, memory or storage beyond the free limits
- **THEN** a `precondition` fails the plan with a message naming the Always Free limit

### Requirement: No variable reaches a paid resource
The stack's variables SHALL be limited to tenancy, region (default `uk-london-1`), parent
compartment, optional SSH public key, optional domain and release channel. Shape, size, database
tier, vault type and key protection mode SHALL be fixed in the configuration. An SSH key SHALL NOT
open port 22. Every variable SHALL appear in `schema.yaml`.

#### Scenario: New variable
- **WHEN** a variable is added to the stack
- **THEN** the `tests/iac` variable check fails until the change is reviewed and the list updated

#### Scenario: SSH key given
- **WHEN** `ssh_public_key` is set
- **THEN** it is installed in the instance metadata and the security list still opens only 443

### Requirement: Secrets stay out of configuration and outputs
The ADB admin password SHALL be generated by Vault and passed as `secret_id`; no password, wallet
or secret content SHALL be a variable or an output.

#### Scenario: Outputs
- **WHEN** the stack is applied
- **THEN** its outputs are only identifiers, the public IP and the Zebra URL

### Requirement: Plan scan against the Always Free allowlist
`scripts/oci_plan_scan.py` SHALL read `terraform show -json` output and fail (exit 1) when a
managed resource is not on `deploy/oci/free_tier_allowlist.yaml`, breaks its type's `max_count`,
`require` or `max` rule, leaves a required value unknown at plan time, or when the plan's total A1
OCPU, A1 memory or block storage exceeds the limits. It SHALL exit 0 on a clean plan and 2 on
unreadable input.

#### Scenario: Bad plan per rule
- **WHEN** a plan has an unlisted type, a paid shape, more than 2 OCPU or 12 GB, a second
  instance or ADB, over 200 GB of storage, `is_free_tier` false or unknown, a non-DEFAULT vault,
  an HSM key, a reserved IP, a load balancer, NAT gateway or DRG, or an Archive bucket
- **THEN** the scan fails and names the resource and rule

#### Scenario: Real plan
- **WHEN** the stack's own plan is scanned
- **THEN** the scan passes

### Requirement: CI checks the stack without credentials
The `iac` CI job SHALL run `scripts/oci_iac_check.sh`, which runs `terraform fmt -check`, `init`,
`validate`, `terraform test` with a mocked `oci` provider, and a plan with throwaway credentials
followed by the plan scan, in a pinned Terraform container. It SHALL need no OCI credentials and
SHALL never apply.

#### Scenario: Pipeline
- **WHEN** a pipeline runs
- **THEN** the `iac` job passes without any OCI credential variables and creates nothing in any
  tenancy
